Prashna Software Design Document

Overview

Prashna is a single-process live Q&A and quiz application for training sessions, lectures, and workshops. One FastAPI application serves role pages, JSON APIs, WebSocket update hints, uploaded media, and the built Vite frontend. One SQLite database stores durable state, and one uploads directory stores quiz images.

Tech Stack

  • Backend: Python, FastAPI, SQLAlchemy sync ORM, SQLite, uvicorn.
  • Frontend: Vite, TypeScript ES modules, plain HTML, shared CSS.
  • Auth: bcrypt, signed admin cookies, GitHub OAuth, moderator keys, participant voter-token cookies, and in-process throttling.
  • Deployment: GHCR image, docker compose, nginx TLS reverse proxy, and persistent database/uploads volumes.
  • Verification: pytest/httpx, Playwright, Ruff, ESLint, Stylelint, TypeScript checking, and GitHub Actions.

Drivers & Constraints

  • Support the current admin, moderator, participant, projector, quiz authoring, reporting, and operator workflows.
  • Commit state before live update hints; recover clients through HTTP refetch.
  • Preserve quiz history through immutable quiz-version snapshots.
  • Keep the baseline to one FastAPI process, one SQLite database, one uploads directory, and one in-memory live-update hub.
  • Keep auth, upload, security header, OAuth, and rate-limit boundaries explicit.

Core vs. Shell / Equivalent Separation

Core rules include authorization predicates, participant resolution, serializers, quiz validation, quiz-version capture, quiz-run transition checks, Q&A visibility rules, feedback aggregation, result tallying, and migration bridge rules. Shell adapters include FastAPI routes, cookies, SQLAlchemy sessions, WebSocket sends, upload IO, static serving, GitHub redirects, Docker compose, and GitHub Actions.

Design Decisions

  • DEC-SINGLEPROCESS: Single-Process Runtime.
  • DEC-HINTREFETCH: Hint Then Refetch.
  • DEC-SQLITE: SQLite with Additive Startup Bridges.
  • DEC-MULTIPAGE: Vite Multi-Page Frontend.
  • DEC-OWNERDELEGATE: Owner and Delegate Authority.
  • DEC-VERSIONEDQUIZ: Immutable Quiz Versions.

Test Strategy

The Markdown source is the traceability source of truth for full TEST-to-requirement coverage. The required obligations are: TEST-AUTH-BOUNDARY, TEST-SESSION-LIFECYCLE, TEST-QA-FLOW, TEST-QUIZ-HISTORY, TEST-LIVE-REFRESH, TEST-PROJECTOR-STATE, TEST-UPLOAD-SECURITY, TEST-SQLITE-MIGRATION, TEST-DEPLOY-SMOKE, and TEST-DOCS-CONTRACT.

Risks & Trade-offs

  • RISK-BOOTSTRAP: First-Run Bootstrap Exposure.
  • RISK-UPLOADS: Limited Upload Validation.
  • RISK-MIGRATION: Narrow Migration Bridge.
  • RISK-WEBSOCKET: Single-Process Live Hub.
  • RISK-OBSERVABILITY: Operator-Oriented Diagnostics.
